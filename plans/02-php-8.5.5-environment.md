## ⚠️ Decisões críticas para o `router.php`

### 1. `cgi.fix_pathinfo = On` (servidor) — RISCO

**Risco:** Apache pode passar `/router.php/X.html` (PATH_INFO) e executar router.php com path controlado pelo usuário. Isso é uma porta aberta para execução de código malicioso.

**Mitigação obrigatória** no `.htaccess`:

```apache
<IfModule mod_php.c>
    php_flag cgi.fix_pathinfo 0
</IfModule>
```

**Validação adicional no router.php** (defense in depth):

```php
if (isset($_SERVER['PATH_INFO']) && $_SERVER['PATH_INFO'] !== '') {
    http_response_code(404);
    exit;
}
```

### 2. `display_startup_errors = On` (servidor) — RISCO MENOR

**Risco:** Vazamento de info do servidor em erros de inicialização. Mitigação: nosso `router.php` usa `declare(strict_types=1)` + try/catch + não emite warnings. OK para nosso caso, mas é boa prática setar `Off`.

### 3. `expose_php = Off` ✅

Boa configuração. Manter.

### 4. `cgi.force_redirect = On` ✅

Proteção contra acesso direto. Manter.

### 5. `cgi.discard_path = Off` — OK

Não causa problema, mas podemos setar `On` por segurança extra (descarta PATH_INFO antes de processar).
